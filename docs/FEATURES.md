# 功能地图

> 文档索引：[docs/README.md](README.md) · 相邻：快速开始 [GETTING_STARTED.md](GETTING_STARTED.md) · 账号运营 [ACCOUNT_MATRIX.md](ACCOUNT_MATRIX.md)

按「一类事」归类，每项给出一句话说明、界面入口与详细文档。改代码前建议对照 [ARCHITECTURE.md](ARCHITECTURE.md)
确认它落在哪一层（API 负责 Bot 侧，Worker 负责用户号侧）。

## 1. 账号资产

| 功能 | 做什么 | 入口 |
|---|---|---|
| 账号管理 | 全列 + 全量筛选 + 批量操作 + 详情抽屉；设备指纹、健康分、代理与分组一屏可见 | 账号 → 账号管理 `/accounts` |
| 登录向导 | 手机号 → 验证码 → 两步验证，逐步拿到会话并加密入库 | 账号管理 → 登录向导 |
| 批量导入（四种格式） | 手机号清单 / StringSession 串 / `.session` 文件 / tdata 目录 zip；先预览再落库 | 账号管理 → 批量导入 |
| 深度验活 | 读权限 + 授权会话数 + 可选写探测，复算 0-100 健康分 | 批量操作 → 深度验活 |
| 官方机制养号 | 按官方客户端节奏上线/翻会话/下线，不发消息；顺带同步服务端下发的限制参数 | 批量操作 → 官方养号 |
| 节流防封 | FloodWait 熔断、活跃时段、动作最小间隔、每日配额；批量设置额度与间隔 | 批量操作 → 设置发送节流 |
| 账号检测 | 勾选 / 全部 / 按分组检测，结果写回账号状态 | 账号 → 账号检测 `/detection` |
| 分组与代理 | 账号分组、代理池（一机一号一出口）、绑定与解绑 | 账号 → 账号分组 / 网络 |
| 租约与心跳 | 一个号同一时刻只被一个 Worker 使用，心跳超时会释放 | 见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 4 节 |

细节（导入格式、去重口径、验活扣分、阶梯数值、官方参数换算）：**[ACCOUNT_MATRIX.md](ACCOUNT_MATRIX.md)** 第 1-6、10 节。

## 2. 群情报（入群即采）

| 功能 | 做什么 | 入口 |
|---|---|---|
| 入退群流水 | 事件回调静默记录谁进了 / 出了哪个群、被谁拉进来；不发言、不回应 | 群情报 `/group-intel` → 选中群 → 入退群 |
| 群档案 | 群名、用户名、类型、成员数、简介、邀请链接、创建时间、采集进度 | 群情报 → 群档案表 |
| 成员名单 | 用户 ID、用户名、昵称、机器人 / 会员 / 管理员标记、在群状态、来源 | 群情报 → 选中群 → 成员 |
| 按链接采集群员 | 粘贴 `t.me/xxx`、`t.me/+hash`、`@username`、数字 ID，自动解析、可选加入、采完可退出 | 群情报 → 按链接采集 |
| 采集进度 | 每条任务的阶段（解析 → 定位/加入 → 采集中 N/M → 完成）与失败原因，5 秒轮询 | 群情报 → 采集进度 |
| 采集后打包 | zip：群总表 + 每群成员明细 + 事件流 + 清单文件 | 群情报 → 打包导出 / 群里详情 → 打包这个群 |

细节（无感三条纪律、链接解析与入群代价、打包结构）：**[ACCOUNT_MATRIX.md](ACCOUNT_MATRIX.md)** 第 7-9 节。

## 3. 营销中心（批量动作）

界面入口统一在 `/campaigns/<功能>`，一次提交一批账号，按**批次**跟踪进度。

| 功能 | 做什么 |
|---|---|
| 素材库 | 文字 / 图片 / 视频 / 文档素材统一管理，批量动作共用 |
| 批量私信 | 一批号各自向目标逐个发消息（可配每号条数、间隔、轮次） |
| 群发 | 一批号各自向指定群发一条消息 |
| 素材群发 | 按素材库内容发给群或私信目标，按号分配不同文本以降低重复特征 |
| 加群 | 邀请链接或公开群，一批号一起进（高风险动作，按 3 倍权重计费） |
| 退群 | 一批号退出同一个群 |
| 强拉进群 | 管理员把指定成员拉进群 |
| 批量改资料 | 统一改名 / 简介 / 用户名 / 头像，支持按号覆盖 |
| 吵群 | 文本池 + 随机间隔连续发言 |
| 拟人发言 | AI 按人设生成话术连续发言（可带入群内上下文） |
| 批次进度 | 按批次查每条任务的进度、取消未完成任务、导出结果 |

拟人化的实现细节（文本池按号分配、口语化微调、随机间隔、上下文）：见 [ARCHITECTURE.md](ARCHITECTURE.md)
与代码 `backend/app/worker/humanize.py`；接口与 payload 见 [API_CONTRACT.md](API_CONTRACT.md) 第 10、18 节。

## 4. 会话与收件箱

| 功能 | 做什么 | 入口 |
|---|---|---|
| 会话收件箱 | 群聊 / 私信 / Bot 私信统一入口，列表 + 消息流 | 消息 → 会话 `/dialogs` |
| 实时推送 | 新消息通过 WebSocket 推到页面，无需刷新 | 同上，协议见 [API_CONTRACT.md](API_CONTRACT.md) 第 8 节 |
| AI 草稿 | 按上下文生成回复草稿，人工确认后再发 | 会话详情 |
| 同步会话 | 把某号加入的群与私信拉进列表（批量操作里也有） | 账号管理 → 同步会话 |

## 5. 任务与队列

| 功能 | 做什么 | 入口 |
|---|---|---|
| 任务中心 | 状态汇总、失败原因、批量重试、详情时间线 | 运营 → 任务中心 `/tasks` |
| 队列与优先级 | `FOR UPDATE SKIP LOCKED` 抢任务，优先级 + 可顺延重试 | 见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 3 节 |
| 顺延而非硬发 | 被节流拦下的任务按建议时间重新入队，不硬发出去换 PeerFlood | 同上，及 [ACCOUNT_MATRIX.md](ACCOUNT_MATRIX.md) 第 3 节 |

## 6. Bot 能力

| 功能 | 做什么 | 入口 |
|---|---|---|
| Bot 管理 | Token 掩码存储、Webhook 状态、自动回复资料 | 消息 → Bot 管理 `/bots` |
| Bot 转发 | 规则 + 已转发记录 + 测试消息，把消息转发到员工群 | 消息 → Bot 转发 `/relay` |

> Bot 侧任务由 API 进程处理（aiogram），用户号侧任务由 Worker 处理（Telethon）——两条链路互不影响。

## 7. 运营与治理

| 功能 | 做什么 | 入口 |
|---|---|---|
| 工作台 | 在线/异常/失败任务、在线趋势、Worker 心跳、队列积压、通知流 | 总览 → 工作台 `/` |
| 成员分配 | 谁可以操作哪个号（操作员只能看到分配给自己的账号） | 运营 → 成员分配 `/assignments` |
| 操作记录 | 谁在什么时间对哪个号做了什么（含导入、养号、采集、导出） | 运营 → 操作记录 `/audit` |
| 导出 | 账号、会话、消息、任务、审计、群成员 CSV / zip 打包 | 各列表页右上角 / 群情报打包 |

权限模型与审计口径：**[SECURITY.md](SECURITY.md)**。

## 8. 与外部服务的边界

- **不做**：加粉、拉活、群发到未经同意的人、绕过 Telegram 限制、任何形式的账号买卖。
- **范围内**：自有账号与自有 Bot 的批量运营、状态巡检、采集与留痕；所有动作走官方接口。
- **风险动作按权重计费**：加群 / 强拉 / 群发 / 吵群算 3 个额度，读取类算 0——见节流文档。
- 采集是**只读**的：不用私有接口，不做不可回滚的破坏性操作，采完可退出群。
