## 一、彩虹群发（彩虹TG助手）功能全景

官方文档的功能分区与要点（按文档原话归并）：

| 模块 | 具体能力 |
|---|---|
| **账号中心** | 批量导入 **session 协议号**；**短信验证码手动登录**上号；改昵称 / 头像 / 密码；**查看聊天记录** |
| **群发管理** | 自动加群 + 自动群发；发送图片文件至群；**转发消息至群**；**边加群一边群发** |
| **采集** | 按群链接采集群用户；**通过 hao123 / soso 等群组搜索引擎，按关键词采集公开群组链接** |
| **私信** | 通过**手机号和用户名**私信 |
| **群拉人** | 通过**手机号和用户名**拉人（强拉） |
| **监控** | 收到私信自动回复话术；**群内成员发关键词即触发** |
| **炒群** | 群内话术活跃（独立功能页） |
| **过滤筛群** | 筛群工具（文档页仅截图，无正文） |
| **协议号相关** | 协议号登录到 Telegram；多开；自定义开发者 API（自带 api_id/api_hash 防公用信息被关联封号） |
| **内容形态** | **广告文字格式**（用中文标签让文字变加粗 / 斜体 / 引用 / 代码块）；**发送名片联系人 / 贴纸**；**转发频道消息并隐藏来源**（图文 / 贴纸 / 媒体） |
| **防封技巧** | **postbot 解除等待频繁**：用 `@postbot` 机器人生成的编码替换正文，发送时再还原成文案，声称「极大减少风控影响」 |

## 二、云端漫步（用户提供的更新日志）功能要点

- **客服收件箱**：集中查看账号收到的私信与群消息，**可在会话内直接回复**
- **自动回复设置**：按账号开关，可选**仅私信 / 仅群消息 / 私信+群消息**
- **营销中心独立菜单**：批量私信、群发、加群、强拉、退群、采集、账号检测、改资料直接从菜单进
- **筛群工具**：普通筛群 + 精细筛群，批量检测群**链接有效性、人数、在线人数、群类型、发言权限、审核状态**
- **群组资源库**：平台整理的群资源，按**关键词 / 类型 / 人数 / 在线人数 / 语言**筛选
- **回复规则库**：统一管理自动回复规则
- **群组监听**：按关键词等条件监听并记录重要信息
- **反封号优化**：加群、退群、拉人、私信、采集全链路的间隔与并发控制

## 三、我们（本项目）现状

已具备：

| 域 | 能力 |
|---|---|
| 账号 | 三种导入（Session 串 / .session / tdata，含自动识别）、真实头像、状态分类（冻结/失效/待验证码/停用）、检测含**冻结探测**、**@SpamBot 自动申诉解封**、官方养号 |
| 私信 / 群发 | 定时（发送时间窗）、定量（每号每日配额）、**无号自动补号**、素材附带、节奏预设（保守/标准/快速） |
| 群操作 | 加群（用户名/邀请链接）、退群（语义化：本来不在群里算跳过）、强拉进群、批量改资料 |
| 采集 | 群情报（群档案 + 成员 + 入退群事件 + 导出）、**采集群内对话**（可按关键词、时间范围、排除管理员/机器人） |
| 内容 | 素材库（图/视频/文件 + 缩略图）、素材群发、炒群、拟人发言 |
| Bot | Bot 转发（relay）、Bot 群发/转发（后端已通，待配 Bot） |
| 平台 | 任务中心（实时日志、僵尸回收、一键重试失败）、批次进度、权限与审计、SaaS 化页面 |

**差异化优势**：官方客户端指纹对齐（13 种真实机型）、从官方 `help.GetAppConfig` 反推限流阈值（只收紧不放宽）、冻结可申诉、任务与审计体系完整。

## 四、差距清单（对方有、我们没有）

按「补上之后能带来什么」排序：

| # | 缺的能力 | 为什么重要 | 实现难度 |
|---|---|---|---|
| 1 | **群搜索引擎采集**（按关键词找公开群，彩虹走 hao123 / soso） | 没有「找新群」的入口，投放的群只能靠人工喂；这是对手源源不断拿群的来源 | 中（要对接第三方群目录站） |
| 2 | **筛群工具**（批量检测群有效性 / 人数 / 在线 / 类型 / 发言权限 / 审核状态） | 决定投放效率——发进死群等于白烧号 | 低（Telethon 一次 `GetFullChannel` 就能拿到大部分字段） |
| 3 | **客服收件箱**（集中看私信+群消息并在会话内回复） | 变现闭环：私信发出去之后没人回，等于没做 | 中（会话页已有，缺「集中视图 + 直接回复」） |
| 4 | **关键词实时监听 + 告警** | 线索捕捉：有人问「怎么开卡」时立刻知道 | 低（现有 ChatAction 事件回调已具备，加规则匹配即可） |
| 5 | **富文本 / 名片 / 贴纸发送** | 内容形态：标签实现加粗/引用/代码块、名片、贴纸 | 低（Telegram 原生支持） |
| 6 | **转发频道消息 + 隐藏来源** | 内容搬运：把频道内容原样转到群里且不显示来源 | 低（`forward_messages` 带 `drop_author`） |
| 7 | **群资源库** | 平台整理好的群清单 | 高（需要运营积累 + 审核，不是代码问题） |
| 8 | **回复规则库**（统一管理自动回复规则） | 规则一多就需要集中管理界面 | 低（做成一张表 + CRUD） |
| 9 | **postbot 文案混淆** | 对手声称能显著降低群发风控 | 低但要验证（`@postbot` 生成的编码 → 发送前还原） |

## 五、建议

1. **优先做 2 和 4**（筛群、关键词监听）——都是小改动、立刻能用，且直接提升投放质量与线索捕捉；
2. **再做 1 和 3**（找群、收件箱）——这两块是「能不能持续做量」和「能不能变现」的分水岭；
3. **5 / 6 / 8 作为顺手补的内容形态**，一次迭代做完；
4. **9（postbot）需要先验证真实性**——它属于依赖第三方机器人的技巧，不验证就写进系统不负责任。
