# 安全与边界

> 文档索引：[docs/README.md](README.md) · 相邻：部署 [DEPLOYMENT.md](DEPLOYMENT.md) · 功能地图 [FEATURES.md](FEATURES.md)

这套系统持有**你自己的** Telegram 会话串，等于持有账号的登录态。安全底线是：密钥不外泄、动作有留痕、
行为不过界。下面按「凭据 → 权限 → 留痕 → 行为边界 → 数据留存」讲清。

## 1. 凭据与加密

| 数据 | 存放方式 | 丢了会怎样 |
|---|---|---|
| 会话串（StringSession） | `SESSION_ENCRYPTION_KEY` 对称加密后存库（`tg_accounts.session_enc`） | 密钥丢失 → 所有会话作废，只能逐号重新登录 |
| 手机号 | 密文存 `phone_enc` + 明文哈希 `phone_hash`（仅用于去重）+ 脱敏展示 `phone_masked` | 密钥丢失 → 无法还原明文（界面只显示脱敏值） |
| Bot Token | 掩码展示，密文存库 | 泄漏等于 Bot 被接管，需去 @BotFather 重签 |
| 登录密码 | 单向哈希（`hash_password`） | — |
| JWT | 由 `SECRET_KEY` 签发 | 换 `SECRET_KEY` 会让所有登录态失效 |

规则：

- `SESSION_ENCRYPTION_KEY` 与 `SECRET_KEY` **只放 `.env`**，不进版本库、不进聊天记录；
  备份时与数据库备份**分开保存**（放一起等于把锁和钥匙放同一个箱子）。
- 每个部署单独申请 `TELEGRAM_API_ID`；共用凭据一旦被限流，会牵连所有使用者。
- 日志里不打印会话串与 Token：代码里输出手机号一律走脱敏值（`+1202****0143`），
  排查问题时也请先脱敏再贴出来。

## 2. 权限模型

| 角色 | 能做什么 |
|---|---|
| 管理员（admin） | 全部：账号建档与导入、分配、批量动作、Bot 管理、审计查看、导出 |
| 操作员（operator） | 只能操作**分配给自己的**账号：看会话、发消息、跑批量动作；看不到别人的号，也没有分配权 |

- 归属校验统一走「可见账号集合」：列表接口默认过滤，详情接口越权返回 403。
- 未分配的新号默认对操作员不可见，需管理员在「成员分配」里指派。
- 生产建议：一人一号段，不要多人共用一个管理员账号——审计记录只到用户名一级。

## 3. 审计与留痕

`audit_logs` 记录「谁在什么时间对哪个对象做了什么」，包括但不限于：

| 动作 | 记录内容 |
|---|---|
| `account.create` / `account.bulk_import` | 建档与批量导入的批次、成功/失败/重复条数、导入方式 |
| `account.bulk_throttle` / `account.bulk_warmup` | 节流参数变更、养号活动参数 |
| `account.bulk_probe` | 深度验活批次与是否做写探测 |
| `group_intel.collect` / `collect_link` / `export_zip` | 采集目标数、任务数、打包的群与行数 |
| `campaign.*` | 每个批量动作的批次、目标范围与参数 |

页面入口：运营 → 操作记录（`/audit`）。审计只增不改，导出为 CSV 便于对账。

## 4. 行为边界（比权限更重要）

技术权限决定「能不能做」，行为边界决定「做了会不会把号搞死」。系统内置的保护：

- **节流四道闸门**：FloodWait 熔断、活跃时段（默认 08:00–24:00）、动作最小间隔、每日配额；
  被拦下的任务**顺延**而不是硬发——硬发换一个 `PeerFlood` 是最常见的封号路径。
- **养号阶梯**：新号 20 条/天起步，随号龄放宽到 200 条/天；连续被限流 3 次额度自动减半。
- **风险动作加权**：加群 / 强拉 / 群发 / 吵群按 3 个额度计费，读取类（同步、检测、改资料）不计费。
- **官方机制对齐**：身份取自官方真实发布版本表；读服务端下发的 `help.GetAppConfig` 限制参数做节流
  （**只收紧不放松**）；养号活动模仿官方客户端的在线与读节奏，不发消息。
  细节见 [ACCOUNT_MATRIX.md](ACCOUNT_MATRIX.md) 第 10 节。
- **无感采集**：群事件只写库不回应；采集只用读接口（`GetFullChannel` / `GetParticipants`），
  成员名单分页限速；采完可选择退出群，不在群里留人。

明确不做的事：

- 不加粉、不拉活、不向未同意的人群发、不绕过 Telegram 的限制、不做账号买卖；
- 不用私有/逆向接口，不做不可回滚的破坏性操作；
- 不给「白嫖风控」的用法做自动化（例如高频换号注册）。

> 一句话：**这套系统帮你把自有账号管好，不帮你把别人的号搞乱。**

## 5. 数据留存与清理

| 数据 | 建议 |
|---|---|
| 消息与群成员采集结果 | 按运营周期清理（导出 zip 归档后删库内明细），避免长期堆积 |
| 入退群事件流水 | 一般保留 30–90 天；`/api/group-intel/events` 支持按小时窗口查询 |
| 素材文件 | 存在 `MATERIALS_DIR`（Compose 是独立卷），清理前先确认没有进行中的素材群发 |
| 审计日志 | 长期保留（只增不改），体量大时按年归档 |
| 导出文件 | 下载到本地后，服务端不要留副本；CSV 里含明文用户名，注意存放位置 |

## 6. 上线前自查

- [ ] `.env` 权限 `600`，内容已备份且与数据库备份分开放。
- [ ] 数据库与 Redis 未暴露公网；前端只有 443 对外。
- [ ] Bot Webhook 是 HTTPS 且能收到消息（Bot 管理页能看到 Webhook 状态）。
- [ ] 至少一个操作员账号验证过「看不到未分配的号」。
- [ ] 审计页能看到刚才的操作记录。
- [ ] 已跑过一次恢复演练（[OPERATIONS.md](OPERATIONS.md) 第 3 节）。
